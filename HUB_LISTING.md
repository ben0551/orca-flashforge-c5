# Orca Cloud hub listing

Copy-paste material for this plugin's page on the Orca Cloud hub, kept here so the
listing text does not drift from the code.

This repository holds **one** plugin. The 3mf Converter has its own repository
(`orca-3mf-converter`) and its own listing, because Orca Cloud connects a repository
to exactly one plugin.

## Checklist before publishing

| # | Requirement | Status |
|---|---|---|
| 1 | Plugin file carries a target-OS suffix — `any` for a pure Python plugin | Done: `flashforge-c5_any.py` |
| 2 | A `LICENSE` file at the repo root | Done: MIT |
| 3 | `.py` only, no binaries/archives/symlinks in the upload | Done: one `.py` each |
| 4 | Release tag is a semantic version greater than the one listed | `v1.3.1` on first publish |
| 5 | Repo connected in the portal: **Plugins → Shared → the plugin → Edit plugin → GitHub publishing** → `ben0551/orca-flashforge-c5` → Connect | Not yet — manual step, needs your login |
| 6 | Portal metadata filled: compatible OrcaSlicer version, supported OS, tags | Not yet — set in the portal, once per listing |
| 7 | Listing icon uploaded (set in the portal, not in plugin metadata) | Ready: `icon.png` (512), `icon-256.png`, `icon-128.png` |

Once 5 and 6 are done, publishing a new version is: push, create a GitHub Release
tagged `vX.Y.Z`, publish it. `.github/workflows/publish-orcacloud.yml` uploads the
file, the tag becomes the version, and the release notes become the changelog.

**A repository connects to exactly one plugin.** Orca Cloud fails a run with a 401 if
the repository is connected to none or to more than one, which is why the 3mf
Converter is a separate repository rather than a second listing here.

## ⚠️ Read this first: the hub needs a Nightly build

Orca Cloud's own help page states that Plugins are a **Beta feature that currently
works only with current OrcaSlicer Nightly builds** — "stable releases without the
Plugins feature will not show or load Orca Cloud plugins."

That is a different gate from the plugin *system* itself, which shipped in
OrcaSlicer **2.5.0** and is what loads a locally installed `.py`. So:

- **Local install on 2.5.0** — works today. This is how you are testing now.
- **Hub listing** — the listing can be created now, but subscribers on 2.5.0
  stable may not be able to see or activate it until they run a Nightly.

Worth checking the hub's current state before investing in the listing, and worth
putting a line in the listing description saying which OrcaSlicer build it needs.

## Listing text

The icon lives at `icon.png` (512px), with `icon-256.png` and `icon-128.png`
beside it. It is generated by `tools/make_icon.py`, so tweaking it is a matter of

### The listing

**Name:** FlashForge Creator 5 Device Tab

**Types:** two capabilities — Pages and Printer Connection. See
*Capability types and the hub* below: a plugin is not listed under one type.

**Compatible OrcaSlicer:** 2.5.0 or newer

**Supported OS:** any (pure Python, standard library only)

**Tags:** `flashforge`, `creator-5`, `creator-5-pro`, `printer-agent`, `lan`,
`local`, `no-cloud`

**Short description**

> Print to a FlashForge Creator 5 / 5 Pro straight from OrcaSlicer. FlashForge's
> firmware hides the printer behind its own cloud app, so OrcaSlicer will not send
> to it or show its status. This plugin talks to the printer's own local API on
> port 8898 instead: a FlashForge C5 tab with live status, temperatures, the
> 4-slot material station, job control, and the files already on the printer with
> a plate preview and one-click reprint — plus a printer agent so OrcaSlicer's own
> Send and Print buttons work too. If the printer is already set up in OrcaSlicer
> under its **Flashforge** host type, the plugin reads the address, serial and
> access code from there rather than asking again.

**Long description**

> **The problem.** A Creator 5 registers with a slicer as a cloud-bound
> Bambu-style device, so OrcaSlicer offers no way to upload to it or read its
> status — you have to hand the file to FlashForge's own app. The printer's
> firmware, however, exposes a complete local HTTP API, and this plugin uses it.
>
> **What you get**
>
> - **FlashForge C5 tab** — live print status and progress, nozzle and bed
>   temperatures, the 4-slot material station with the colour loaded in each slot,
>   a **live camera view**, pause / resume / cancel, chamber light and
>   clear-platform, and a browser for the files already on the printer with a
>   plate preview and one-click reprint.
> - **The camera, handled properly** — the firmware gates its MJPEG server and
>   serves one viewer at a time, so the tab starts the stream when you ask, closes
>   it when you stop or leave, and hands the camera back rather than leaving it
>   wedged.
> - **Plate previews** — the firmware keeps a thumbnail beside every stored job
>   and serves it from its own `/gcodeThumb` route; the tab fetches it so you can
>   see what a file is before reprinting it.
> - **OrcaSlicer's own buttons** — a printer agent so **Send to printer** and
>   **Print** work directly (needs OrcaSlicer's experimental "use printer agents"
>   preference). This is the sending path.
> - **No retyping** — if you already set this printer up in OrcaSlicer's own
>   **Flashforge** host type, the plugin reads the address, serial number and
>   access code straight out of that printer preset and fills its own panel in.
> **Two things it handles that the raw API does not**
>
> - OrcaSlicer exports `.gcode.3mf` bundles, which this firmware accepts, lists,
>   and then fails to print — the plugin extracts the inner G-code and uploads
>   that instead.
> - The firmware pads idle-state job fields with uninitialised memory, so the
>   plugin zeroes the job block when the printer is idle rather than showing
>   garbage.
>
> **Privacy.** Your serial number and LAN check code live in `settings.json`
> beside the plugin at mode 0600, or in your OrcaSlicer printer preset if you had
> already set one up — either way they are sent to nothing but your printer. This
> plugin talks to your printer and to nothing else. It has no dependencies.
>
> **Requirements.** OrcaSlicer 2.5.0 or newer. The printer on the same LAN, with
> its serial number and LAN check code to hand (printer touchscreen → Device →
> About, and → Network) — unless you already set the printer up in OrcaSlicer,
> in which case the plugin reads them from there.

## Capability types and the hub

A plugin is **not listed under a single type**. From the wiki's Plugin Types page:
there is "no separate `type` declaration in the metadata" — the capabilities the
plugin registers determine which workflows can run it, and the Plugins dialog
shows *one row per registered capability*, each with its own enable checkbox and
its own type label. The types are **Script**, **Slicing Pipeline**, **Printer
Connection**, **Pages**, and **Resource Texture** packs.

So this plugin presents two rows — Pages (the FlashForge C5 tab) and Printer
Connection (the printer agent). Neither appears in the listing card's dropdown
(Script / Slicing-pipeline / Resource textures), so there is nothing to match and
nothing to contort; that dropdown describes a narrower set than the capability system
supports.

The printer-agent type is not even ours to set: `PrinterAgentBase.get_type()`
already returns `orca.PluginType.PrinterConnection` (`"printer-connection"`) and
the docs say explicitly, *"You do not override it."*

The hub still asks for a type on the listing card, and its dropdown only offers
Script / Slicing-pipeline / Resource textures — no Pages or Printer Connection.
That dropdown is likely just behind the beta, but it is worth a note to the Orca
Cloud team when submitting rather than guessing. The **Compatible OrcaSlicer
Version** field is the right place to record the 2.5.0 floor.

## The "Adventurer plugin" is not a plugin

Worth stating because it changes the pitch: the existing FlashForge Adventurer 5
series support is **built into OrcaSlicer core**, not published as a hub plugin.
PR #12991 ("Add Flashforge Adventurer 5 series local send workflow with IFS
mapping", @marianomd) merged to main in May 2026, and the 2.4.0-beta release notes
describe it: "Flashforge Adventurer 5 series, including local printer discovery,
saving the printer serial number and access code, and a Flashforge-specific send
dialog."

There is therefore no Adventurer plugin listing type to match. The equivalent move
for the Creator 5 would be contributing it upstream the same way — PR #12991
included a commit titled "Generalize Flashforge local API handling", so the core
code is already generalised across FlashForge machines. That is the long game;
this plugin is the one that works today.

## Differentiation

The comparable FlashForge plugins, as of 2026-11-19:

| Repo | Covers | Approach | Licence | Notes |
|---|---|---|---|---|
| `UshMask/flashforge-device-tab` | several printers | Device tab panel | MIT | **Read-only.** Single file, has docs and tests |
| `monkyja/flashforge-connect` | Creator 5 Pro | Pages, **FlashForge cloud account** login (Linux keyring) | AGPL-3.0 | README states the full send "has not been validated with the real printer" |
| `djvalic/kiln-orca` | AD5X only | IFS tool→slot mapping over Moonraker | GPL-3.0 | Requires Kiln OS custom firmware |
| **ForgeBridge** (closed source) | MakerWorld / Printables / Creality Cloud / makeronline / Snapmaker Space → FlashForge | Web app + Chrome extension + an OrcaSlicer panel that converts a dragged `.3mf` | proprietary, free | The same conversion idea, and the one to beat on polish; Windows-only panel as of 2026-11 |

Where this plugin stands apart:

- **LAN only, no FlashForge account.** `flashforge-connect` logs in to FlashForge's
  cloud; this one talks straight to the printer on port 8898 and needs no account.
- **Read and write.** The Device-tab panel is read-only; this does upload, print,
  pause/resume/cancel, reprint, light and clear-platform.
- **The send path is exercised.** The mock Creator 5 enforces the real request
  shape and the protocol matches a client verified against firmware 2.0.0 —
  `flashforge-connect` says plainly that its send is unvalidated.
- **The `.gcode.3mf` trap is handled.** OrcaSlicer exports a bundle this firmware
  lists and then refuses to print; the plugin extracts the inner G-code.
- **The conversion and the printing are one plugin.** ForgeBridge converts and
  hands you a project; you still need a way to get it to a FlashForge. Here the
  same plugin owns the printer, so the converted project opens into the slicer
  that is already talking to the machine.
- **The conversion rule is OrcaSlicer's own.** Which settings belong to a machine
  comes from `Preset::printer_options()`, not a hand-maintained key list, so the
  kept/replaced split cannot quietly drift from what the slicer actually does.
- **Permissive licence.** MIT against AGPL-3.0 and GPL-3.0, so it is usable in
  more contexts.
